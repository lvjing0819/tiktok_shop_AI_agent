# Agent API 请求代理与凭据网关（v0.12）

## 执行结构

```text
Agent / Harness（后端：规划、账户选择、参数绑定、分析）
    ↓ 固定请求、一次性能力凭证，不传平台密钥
Docker v3 请求代理（固定程序；network=none）
    ↓ 私有 stdin/stdout RPC，仅一条已绑定请求
凭据网关（受信任后端模块）
    ↓ 固定 Shop HTTP 适配器 / Ads、Social MCP SDK
TikTok 官方服务
```

这里实现的是容器内的固定 API 请求代理，不是把整个 Agent、LangGraph 循环、MCP SDK或HTTP客户端搬进容器。外部 TLS 连接、OAuth 协商/刷新、签名和长期凭据管理仍在网关。网关当前是后端进程内的独立模块，不是独立部署的服务或容器；不能声称已隔离网关/SDK漏洞对主后端的影响。

不开放 HTTP 代理端口，也不把容器接到宿主网络。容器通过已连接的 Docker 标准输入/输出通道提出请求，由执行器转交网关。容器无法绕过该通道直接联网，因此当前没有域名代理、DNS重绑定过滤或可配置网络白名单。上游地址由受信任适配器固定，模型不能提交任意 URL、请求头、镜像、命令或挂载。该实现不等同于开放互联网的联网沙箱。

## 已接入范围

- Harness 工具 `shop.discover`、`shop.query`、`ads.analyze`、`social.analyze` 标记为 `service_with_api_sandbox`，版本2。已完成的历史任务不会自动重跑。
- 自然语言 Shop 查询/店铺发现、Ads账户发现/分析、Social分析，以及 Shop 商品/订单/库存查询接口和 Social直接只读工具调用，使用同一请求通路。
- Shop仅授权店铺列表和三个固定 POST 搜索接口。库存查询允许其原有的商品目录前置查询。授权店铺、Token与连接generation在可信端检查；店铺cipher与买家身份字段不进入容器，平台原始响应只在可信服务中保留以继续原有验证/清洗。
- Ads仍按官方工具元数据与已有只读策略过滤，并再次验证schema。除授权账户发现外，调用必须显式绑定选定advertiser_id(s)。支持start_date/end_date的报表工具仅可查询本期、环比或同比批准窗口；不支持日期参数的工具仍需在报告中说明时间口径限制，不能承诺它经过了时间过滤。
- Social仅允许现有精确只读工具集合；授权身份由当前Social授权和平台决定。OAuth重新授权、断开/API Token替换期间的旧结果拒绝交付。

看板同步/数据源后台轮询、连接建立与验证、OAuth刷新、管理员工具目录检查、百炼模型推理和选品能力保持原路径；不声称项目的所有外部请求都已经容器化。没有接入外部写操作、任意代码、媒体生成、任务级容器复用或完整服务容器化部署。记忆与保留策略不修改。

## 请求控制与审计

每次请求创建独立临时容器，沿用非特权用户、只读根、无宿主挂载、默认seccomp、cap-drop、cgroup限额和回收检查。生命周期是单次请求级，不是多个工具共用的任务级。

一次性能力凭证由服务端随机生成，只通过stdin传给本次容器，不放在环境变量、URL、数据库或审计正文中。授权绑定工作区/run/step/attempt、服务、操作和完整参数；严格核对协议字段，参数或账户被替换、过期、任务取消/版本变化、重复请求均拒绝。没有公开的“申请任意能力凭证”接口。

- 授权最长60秒，且不超过当前步骤期限；上游请求最长45秒，容器执行最长90秒，同时受Harness外层预算约束。
- 每个业务工具执行最多32次网关请求，回复累计最多16MB；单次参数48KB、回复2MB，传输有界。MCP SDK仍在可信端解析上游响应，该回复限制不应描述为覆盖SDK所有底层传输缓冲。
- 请求及回复拒绝凭据字段，回复额外检查已知密钥值；这不是完整DLP或病毒扫描。
- 容器返回必须与本次网关交付完全一致，不能伪造结果。失败或取消后拒绝迟到结果；实际外部只读请求可能已发出，超时不会宣称“没有外部请求”。
- 容器未创建、策略校验失败、Docker不可用时不执行网关业务请求，不回退宿主机直接查询。Ads/Social建立查询会话前检查Docker与镜像可用前提；授权初始化与刷新仍属可信凭据服务。
- 上游过期令牌等原有安全领域错误在容器确认回收后再交回原有刷新/重试逻辑；未确认回收时禁止下一次请求。
- `sandbox_run.gateway`记录服务、操作、校验和、结果大小、放行/拒绝/完成状态，不记录请求正文、回复正文或凭据；不是全流量抓包或全部系统调用审计。Harness任务可从任务中心“沙箱执行记录”查看。自然语言独立查询也写入工作区sandbox_run记录，尚未提供新的独立查询记录列表页面。

## 启用与验收

先安装并启动Docker Desktop，再在项目目录执行：

```sh
.venv/bin/python -m scripts.setup_sandbox
RUN_DOCKER_SANDBOX_TESTS=1 .venv/bin/python -m pytest tests/test_sandbox.py tests/test_api_gateway.py -q
```

设置脚本只用`sandbox/`最小构建上下文生成v3镜像，不会将项目.env、数据库或平台令牌发给构建器。v2镜像不会被新执行器采用。

实际Docker测试用临时数据库和固定网关测试数据，验证容器内请求、断网/UID/seccomp/cgroup前置检查与回收；它不是实时TikTok联调。普通协议/模拟引擎测试不能证明真实容器隔离。实际Docker验收及真实平台查询需分别完成；目前本机尚未发现Docker，不能声称已部署或验证真实联网通路。
