# 经营数据看板

入口 `/analytics.html`，运营助手中的「数据看台 / 经营总览」也会打开此页面。界面采用最新提供的 A-Brain 深色 HTML 原型：对话中心与数据看板在顶部切换，保留极光背景、玻璃卡片、底部输入和折叠维度。原型的全部示例数据、倍数计算、预设 Agent 回复和预设归因文案已移除。Chart.js 随本项目打包，不依赖第三方 CDN。

## 数据与功能

| 模块 | 已实现 | 数据来源 / 限制 |
| --- | --- | --- |
| 店铺与日期 | 已授权店铺发现、市场筛选、自定义1–31天、预设日期、前一等长周期 | MY和TH按各店铺时区；不提供虚构店铺 |
| 订单概览 | 总数、签收/完成、在途/待发、取消、平台GMV及AOV | 订单按创建日期；平台GMV按支付期，包含取消/退款 |
| SKU | 已支付非取消件数、同期涨跌、筛选、关联订单明细 | 未扣售后退货；商品级视频关联数不是SKU转化归因 |
| 结算 | 账单金额、支付状态、正/零/负净额订单、调整流水、分页明细 | 按UTC账单生成日期；订单可以在更早日期创建；净结算不是利润或银行逐单到账 |
| 费用 | 所有非零明细字段、同期变化、非零/明确零/未知订单、对应营收比例、穿透明细 | 使用平台原始正负号；排除补充解释字段重复求和；不把缺字段当0 |
| 地区 | 省/州订单分布 | 只保存L1省州；不保存买家姓名、电话、街道、邮编 |
| 时段与状态 | 店铺当地24小时时段、订单状态、平台取消原因 | 没有物流异常明细时不编造拒收/丢件/退货原因 |
| 渠道 | 视频、直播、商品卡归因GMV | 使用平台Shop Performance；不冒充渠道订单数或强制凑成100% |
| 达人 | 联盟订单、件数、实际/预估佣金、排序 | SETTLED且有金额才算已知实际；空对象未知；未匹配不等于自营；达人订单可能跨SKU重叠 |
| 对比与导出 | 跨店铺原币对比、CSV导出、布局密度切换 | 不直接求和MYR和THB；CSV包括来源完整性和口径 |
| 数据解读 | 本地计算信号、百炼真实问答 | 服务器重读当前筛选；仅发送获准的经营汇总，不发送订单ID/买家资料/密钥；不可执行修改 |

尚未实现：SKU级广告投放/消耗/ROAS归因、物流异常与完整售后原因、未结算订单的全量资金追踪、仓库API。界面明确显示对应数据限制，保留后续扩展入口。

## API

所有接口复用工作区 `X-Shop-ID` 和可选 `Authorization: Bearer APP_TOKEN`。单一所有者本地工作台，不是多用户身份系统。

- `GET /api/analytics/shops`：已授权店铺、时区、币种、来源列表。
- `GET /api/analytics/dashboard?start_date=YYYY-MM-DD&end_date=YYYY-MM-DD&site=MY&shop_id=ALL`：当前和前一等长周期，按店铺返回orders/finance/affiliate/performance及source coverage。
- `POST /api/analytics/ensure`：进入看板或切换日期时自动检查本期和对比期，复用覆盖所选店铺的活动任务，只在准确日期窗口缺少来源时创建同步；最近失败有5分钟自动重试冷却，人工刷新可立即重试。
- `POST /api/analytics/refresh`：相同日期/店铺筛选，返回202和持久化同步任务；不会等待所有远端查询完成。
- `GET /api/analytics/refresh/{job_id}`：进度、活动来源、失败/部分来源。相同筛选的活动任务复用同一ID。
- `GET /api/analytics/details`：同一筛选，加`selected_shop`，`kind=orders|sku|expense|settlement`；SKU/费用加`field`，费用`zero=true`查明确零净额；`page`/`page_size`分页。
- `GET /api/analytics/export`：当前筛选的UTF-8 CSV，包含口径与完整性，并防范电子表格公式注入。
- `POST /api/analytics/ask`：日期筛选和question，返回真实百炼解读及来源状态；demo模式不会返回预设分析。

## 刷新与恢复

运行正常的API和 `python -m app.worker` 即可，不需要另起服务。后台优先处理运营任务，再领取看板刷新和原有订单定时同步。每次领取只处理一个来源，然后释放任务；最新查看的日期范围优先于旧范围和周期性刷新。正在进行的单个来源最多运行300秒，不强行中断已发出的远端请求。看板刷新使用独立的持久化任务记录和租约，长分页请求前续约；进程退出后可在租约过期后重领，已完成来源保留。订单、结算按实体去重存入本地关系表并维护每天的完整性；联盟、平台GMV和视频仍按准确查询区间保存，避免错误累加区间指标。

进入数据看板或切换日期时，先按店铺时区从本地筛选订单、按UTC账单日期筛选结算，再自动补齐缺少的日期和平台来源，并显示任务进度和逐项读取结果。已存在的完整或部分快照不会因自动检查而重复抓取；点击「刷新真实数据」可强制重读所选周期及对比周期。页面每60秒重读本地快照，跨日产生的新日期窗口不会拿上个窗口的数据冒充。地区、订单状态、时段、渠道和达人明细默认展开，也可自行收起并保留本机偏好。这不是平台实时推送，平台分析本身也有`latest_available_date`。没有启动worker会显示等待；失败不会覆盖上次成功数据。来源区显示完整/部分/未同步、抓取时间、请求数量；旧快照可以手动刷新。

自动补齐任务只安排缺少的来源/日期，不会因为对比期缺少两项而重新抓取已有的八项。日期切走再切回时会重新关联后台任务并恢复进度；过期页面请求不会覆盖当前筛选。读取遇到临时网络异常、HTTP 429或500/502/503/504时最多尝试3次，只有明确的令牌过期错误才强制刷新令牌，权限错误不会盲目重试。

日历先选择起止日期，点击「应用周期」才提交；翻月、点选日期、选择预设期间保持弹窗打开，Escape或点击外部关闭。打开时定位到起始月，邻月的有效过去日期也可选择。前端 `npm --prefix frontend test` 使用实际页面与生产事件处理器，回归验证双击选区、翻月、30天预设及日期切回后的同步恢复。

每个来源分页上限20页，每页最多100条，每个来源超时300秒；达到上限保留partial，不声称全量。订单明细按50个订单一批查询。业务数据只在本地数据库，授权仍保存在既有加密存储；均不会纳入Git。

## 本地明细与周期性同步

- `analytics_entities_v1`：工作区、店铺、来源、实体类型和平台ID作为联合主键。订单只存一份最新明细；结算保存账单以及按账单ID+流水ID去重的交易，不以订单ID去重流水。复合日期索引用于筛选，明细分页使用SQL LIMIT/OFFSET，读取不加载全库。
- `analytics_days_v1`：区分每天完整、部分与未同步。完整空结果可以统计为0；缺失日期保持未知。重叠范围的完整明细可以直接复用，跨空缺范围仅展示已知部分并补抓空缺日期。
- 订单明细按50笔、结算按每份账单保存读取检查点，并更新`data_version`。前端按检查点刷新，已读取的数据不必等待整个来源完成。金额以Decimal计算，每笔费用只解析一次；没有把货币转成浮点累计。
- 第一次进入看板会为所选已授权店铺登记后台刷新。默认每900秒刷新最近7天订单与结算，本期/对比期和所选日历不影响周期性任务。未完成的同店铺周期任务不会重叠。`ANALYTICS_SYNC_INTERVAL_SECONDS=0`可关闭，非零最短300秒；`ANALYTICS_SYNC_LOOKBACK_DAYS=1..31`控制回看。区间外的历史状态/迟到结算可能需要人工刷新，不能声称全历史实时更新。
- 平台GMV/渠道、联盟和视频继续按准确区间查询，不将AOV、去重数等区间指标简单按天相加；它们补数期间，已有本地订单和结算照常展示。

### 已有数据迁移

停止API和worker后运行 `python -m scripts.migrate_analytics_cache --backup /安全的本地目录/shop-before.sqlite --compact`，再启动服务。SQLite脚本要求全新备份路径；备份包含本地业务及授权记录，须保留在Git之外。迁移逐批处理旧快照，按抓取时间保留更新的实体，成功后移除重复明细数组并保存来源元信息；不支持索引的旧快照原样保留。重复运行不会重复迁移。`--compact`在停止服务时回收SQLite空闲页；普通删除/替换后文件不会自动缩小，但空闲页会被复用。worker也会幂等迁移已登记工作区的遗留快照。

测试包含新日期子区间直接查询、重叠去重、缺失日补抓、店铺/工作区隔离、本地午夜与UTC账单边界、流水与账单复合ID、旧快照迁移、逐账单检查点、切换日期优先级、周期同步和前端在同步进度不变时呈现检查点。

## A-Brain 对话中心

默认首页和 `/?view=chat` 打开 `/analytics.html?view=hub`，看板仍可通过 `/analytics.html?view=dashboard` 打开。五张卡片对应 Leader、商品运营、广告、选品、内容的协作入口，复用现有会话及工具路由服务，不新建另一套 Agent 后端。卡片只补充当前协作角色上下文，真实业务任务仍由已有 Leader / Harness 规划和执行。每个入口的活动会话 ID 在本浏览器按工作区保存，消息和长期记忆继续由服务端存储；历史会话可恢复，新建会话不会删除旧记录。

任务中心、连接设置、订单、实物库存与成本利润保留既有入口。对话浮层使用原生 dialog，支持 Escape 和键盘焦点；支持减少动态效果偏好。
