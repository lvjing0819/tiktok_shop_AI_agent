# 统一运营会话

v0.5 复用现有 `POST /api/sessions/{session_id}/messages`，不需要另一套聊天入口。离线演示继续明确标识未调用模型；真实查询需要在本机 `.env` 配置百炼。

## 调用路径

```text
会话消息与已确认店铺偏好
  → 百炼选择一个操作
  → 普通回复 / 广告账户发现 / Ads 查询 / Social 查询
  → 专员的 LangGraph 有界工具循环
  → 会话回答 + 执行记录 + 原始工具证据
```

路由只选择本轮一个操作，避免多层主管循环。跨 Ads 与 Social 的联合问题先澄清，不自动展开多团队协作。商品写操作、生成素材、订单与财务不在本次路由工具中。

## 百炼配置

在本机 `.env` 填写（不提交 Git）：

```dotenv
MODEL_MODE=bailian
DASHSCOPE_API_KEY=填入本机真实密钥
BAILIAN_BASE_URL=https://dashscope.aliyuncs.com/compatible-mode/v1
BAILIAN_MODEL=qwen-plus
```

默认沿用项目的北京地域按量付费兼容地址，不能直接搭配 Coding Plan 或 Token Plan 专属密钥。实际密钥、地域、模型权限和配额需要匹配。重启 API 和 worker 后，先通过 `POST /api/model/check` 测试连接。没有密钥时返回明确错误，不会用模拟广告或 Social 数据代替。获取密钥及地域规则见[百炼官方说明](https://help.aliyun.com/zh/model-studio/get-api-key)，不同套餐的密钥与地址配套规则见[官方接入说明](https://help.aliyun.com/zh/model-studio/use-chat-client-or-development-tool/)。

## 查询与追问

- 广告账户每轮从当前授权的 `auth_advertiser_get` 返回匹配。名称支持标准化后的精确和子串匹配；多义或未匹配时列出候选追问，不查询其他账户。没有静态别名映射。
- 确认账户后，使用 `advertiser_info_get` 读取账户时区与币种。相对日期“今天、昨天、前天”在该时区解析，明确日期按账户报表口径传入。
- 缺日期或账户会保存 `pending_ads`，下一轮补充参数后继续原问题。已成功查询的账户保存在当前会话，可处理“那前天呢”。日期仅在本轮明确指定、补齐待办或明确沿用上轮时使用，不随意给默认日期。
- Social 专员接收最近对话、摘要和查询上下文，以解析作品等指代；缺少必要 ID 时查询或追问。历史数字不视为本轮新数据。
- 每轮路由最多一次；专员最多6次工具调用；Ads 账户发现和信息读取最多额外2次。路由与专员合计最多等待210秒（不含进入路由前的历史摘要压缩）。
- 本次未增加自动跨分页抓取；报告仍可能只覆盖部分数据，模型读取有限预览，原始结果保留供核验。

示例：

```text
有哪些已授权的广告账户？
查询示例广告账户A昨天的GMV Max消耗。
那前天呢？
查看当前TikTok账号的粉丝和作品情况。
```

## 接口与证据

1. `POST /api/sessions`：创建会话。
2. `POST /api/sessions/{id}/messages`，请求体 `{"content":"查询问题"}`。
3. 返回原有会话结构，并增加 `query_context`、`last_run`；助手消息增加 `run_id`、`route`、`data_verified`。
4. `GET /api/sessions/{id}/runs`：最近50次执行的元数据，不返回完整工具结果。
5. `GET /api/sessions/{id}/runs/{run_id}`：查看完整工具证据、平台请求编号和关联专员报告 ID。

证据访问同时校验当前店铺与会话。会话消息和本轮执行记录在同一事务提交；模型失败不会覆盖之前的历史。删除会话同时删除其执行记录；Ads/Social 独立报告仍按各自报告接口管理。

`data_verified` 表示存在业务成功的工具证据，不能代替对模型每一句话的事实核验。MCP `isError=false` 或 HTTP 200 不单独构成业务成功，TikTok 返回的业务 `code` 必须为0。待补参数的 Ads 查询不会因账户列表请求成功就被标记为广告表现已验证。

## 当前限制

这是单一所有者本地应用。店铺标识用于分类与查询隔离，不是多用户权限系统。新增路由尚未提供后台队列恢复；请求中断后需要重试。独立专员报告可能已保存而会话写入未完成，这种报告仍留在专员历史中，不会被伪装成成功的会话回复。

百炼与 TikTok 的真实联合测试需要本机有效密钥及已有授权。自动化测试使用模拟模型与接口，不能证明真实模型的工具选择效果。申请演示视频仍为先前的只读原型，不会自动变成此版本的录屏。


## 本机真实联调记录（2026-11-19）

已使用用户在本机配置的 `qwen3.6-plus` 完成百炼连接测试，并从统一会话入口验证：

- 实际获取当前授权的广告账户列表。
- Social 账号资料、粉丝数、公开视频数和获赞查询。
- 按广告账户时区解析“昨天”，查询 GMV Max 消耗。
- 同一会话继续询问“那前天呢”，沿用已确认账户，并切换到正确日期。

联调数据与授权均保存在本机，不包含于仓库。模型输出仍需结合原始证据核验；上述少量真实用例不代表全部工具和复杂问题都已验收。MCP 会话的模型错误会保留可读原因，不会统一误报为授权失败。普通查询传输会话上限为300秒，统一路由仍有210秒的外层上限。
